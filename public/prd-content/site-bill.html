1. 背景与目标

站点后台（商户/集团，如「伯乐 1179」）由集团或公司运营使用。站点账单负责查看本集团账单、在结算后核对金额、提出异议，以及跟踪待支付/逾期/已支付结果。

本期目标：

  • 9 个状态 Tab + 账单明细可交互原型
  • 站点侧完成「核对无误 / 存在异议 / 退回待核对 / 编辑 / 详情」
  • 与总控共用同一套账单状态机；站点不能确认付款

原型入口：/ → 运营 → 站点账单（红色顶栏「包网站点后台」）

2. 角色边界

后台数据范围账单职责
站点后台（本 PRD） 本集团/本公司账单 核对无误、提交异议、编辑异议账单、退回待核对、查看详情
总控后台 全平台账单 确认付款、处理异议编辑、查看全量状态（详见 总控账单 PRD）

原则：账单由系统按自然月结算产生；站点只负责核对与异议；资金确认（确认付款）仅总控可做。运营期费用实时从押金/信用额度扣减（见 §3.1）。

3. 账单状态机

待下发 ──(系统：自然月结束后计算)──→ 待核对 │ ├─ 站点：核对无误 ──────────────────────────→ 待支付 │ │ │ ├─ 总控：确认付款 ──→ 已支付 │ └─ 系统：账单月月底，透支信用额度且未平账 ──→ 已逾期 │ │ │ ├─ 系统：已逾期超过 90 天 ──→ 已坏账 │ └─ 平账：填补透支信用额度 ──→ 待支付 ──(总控确认付款)──→ 已支付 └─ 站点：存在异议 ──→ 存在异议 │ ├─ 总控：安排商务对接处理 ├─ 处理完成后：总控「退回待核对」──→ 待核对 └─ 站点/总控：编辑 已坏账 ──(平账：填补透支信用额度)──→ 待支付 ──(总控确认付款)──→ 已支付

平账：填补透支的信用额度后触发；已逾期 / 已坏账自动改为待支付，总控确认付款后 → 已支付。

已逾期：账单透支信用额度，且账单月月底仍未平账。

已坏账：已逾期超过 90 天自动进入；总控亦可在已逾期 Tab 手动移入。

系统自动流转：待下发→待核对、待支付→已逾期、已逾期→已坏账（90 天）、平账→待支付。

3.1 运营期费用扣款与站点限制

站点运营过程中产生的费用（游戏抽佣、CDN、线路维护、其他资源费等）由系统实时扣减，扣款顺序如下：

  1. 优先从站点押金扣除；
  2. 押金扣至 0 后，从信用额度（授信额度）扣除；
  3. 信用额度亦扣至 0 时，该站点C 端用户游戏、提款受限——无法游戏、无法提款，直至充值或补款恢复可用额度。

实时扣款与月度账单并行。平账后已逾期/已坏账自动回待支付，总控确认付款 → 已支付。

3.2 站点注销自动结算

站点注销完成（开站状态 → 已注销）后，系统自动触发该站点的站点账单最终结算：汇总未结清及在途费用，纳入注销结算流程（含待下发/待核对/待支付/存在异议等存量账单的处理规则见 §11 待确认）。

4. 页面结构

路径：运营 → 站点账单

顶部按钮：查看汇率（各 Tab）；导出报表（已支付 / 全部账单 / 账单明细）

6. 站点侧操作说明

6.1 核对无误

  • 入口：待核对操作列；待核对底部「批量核对无误」
  • 规则：每月月初 6 号 00:00:00 之后可点击直接确认无误（Tab 与「账单状态」列 Tooltip）
  • 确认后：状态 → 待支付，写入操作人/操作时间，账单从待核对消失并进入待支付

6.2 存在异议

  • 入口：待核对操作列（全部账单中状态为待核对时同样展示）
  • 弹窗必填「异议说明」，写入站长备注
  • 确认后：状态 → 存在异议，进入存在异议 Tab；账单推送至总控，由总控安排商务对接线下处理
  • 商务处理完成且总控「退回待核对」后，站点在待核对 Tab 重新核对无误或再次提出异议

6.3 编辑

  • 入口：存在异议操作列
  • 可改：费用明细、实际支付总额 U、滞纳金、推荐折扣、站长备注
  • 保存后状态仍为存在异议，不自动退回待核对

6.4 退回待核对

  • 入口：存在异议操作列（站点侧可在沟通完成后自行退回；常规流程为总控商务处理完成后由总控操作退回）
  • 确认后：状态 → 待核对，站点需重新「核对无误」或再次「存在异议」

6.5 详情

各状态列表均可打开详情弹窗（见第 8 节）。站点在待支付/已逾期/已坏账/已支付仅可查看详情，不可确认付款。

7. 筛选、表格与顶部按钮

7.1 列表筛选（非账单明细）

  • 账单月份（月选择）
  • 品牌字段切换：品牌 ID / 所属公司 / 品牌名称 + 文本输入
  • 站点币种：单选（待下发占位文案为「币种」）
  • 已支付 / 全部账单：增加账单类型（每月账单 / 一次性费用）
  • 全部账单：增加账单状态

7.2 账单明细筛选

账单月份、主站 ID、币种（单选）、游戏类型（电子/真人/体育/棋牌）、厂商名称。

7.3 列表列

品牌名称(ID)、品牌数、所属集团、所属公司、账单月份、账单类型、费用明细、实际支付总额 U、滞纳金、三方固定优惠、本月三方阶梯优惠、本月三方生效优惠、推荐折扣、账单状态、站长备注、操作时间、操作人、操作。

按 Tab 增列：待支付「逾期倒计时」；待核对/存在异议「自动无误倒数」；已逾期「已逾期天数」；已坏账「坏账总额 U」。

列不固定（无 left/right freeze）。表格斑马纹。

7.4 状态展示

已支付 / 正常：绿色；已逾期 / 已坏账 / 存在异议：红色。

8. 详情弹窗与汇率

8.1 详情弹窗

  • 页头：所属集团、主站名称(ID)、账单月份、账单状态、站点余额（可刷新）、站长备注
  • 费用指标一行展示：游戏账单、CDN 流量费、线路维护费、其他费用、费用调整、账单合计、推荐折扣、实际需支付总额 U
  • 明细表：品牌、月份、币种、游戏类型、厂商、投注/有效投注/盈亏、抽佣比例、账单金额、厂商专属优惠、优惠后比例、抽佣金额、折算汇率、游戏账单 U、状态
  • 底部小计 + 红色提示：*报表金额单位转换时可能存在尾数误差
  • 筛选：品牌 ID、币种（单选）、游戏类型、厂商名称；支持导出报表
  • 底部仅「取消」关闭

8.2 查看汇率

弹窗表格：基础币种、兑换币种、站点汇率；底部「关闭」。

9. 字段与计算规则

规则说明
账单金额单位列表「实际支付总额 U」= 详情弹窗本账单合计，单位 U
账单合计游戏账单 + CDN 流量费 + 线路维护费 + 其他费用 + 费用调整
实际需支付总额 U账单合计 + 推荐折扣
CDN 流量费上限 = 当月游戏账单 × 10%，超出自动免除；解析数/节点等级等资源名额不参与封顶
其他费用含 CDN(解析数+节点+IP)、埋点归因(ADJ)、极光、CPF 验证、KYC 验证
费用调整财务每月 5 号前人工导入模板生成
滞纳金已逾期状态下，逾期每多 1 天加收账单总额 0.05%/天，上不封顶（暂不收取）
实时扣款运营期费用优先扣押金，押金为 0 扣信用额度；信用额度为 0 则 C 端无法游戏、无法提款
注销结算站点注销完成后，系统自动触发站点账单最终结算
核对窗口待核对：每月月初 6 号 00:00:00 之后可点击直接确认无误
平账填补透支信用额度后触发；已逾期/已坏账自动改为待支付，总控确认付款 → 已支付
逾期账单透支信用额度，且账单月月底仍未平账 → 已逾期
坏账已逾期超过 90 天 → 已坏账（总控亦可手动移入）

11. 非功能与待确认

非功能

  • 语言：简体中文；主题：红色顶栏 #d72c2c
  • 原型：本地 Mock，状态切换即时反映到各 Tab / 全部账单
  • 与总控同域：站点 /，总控 /master

待确认

  1. 6 号 00:00:00 之前，「核对无误」是置灰还是隐藏？超时未核对是否自动视为无误？
  2. 站点「编辑」是否允许改金额，还是仅允许改异议备注？（原型：金额+备注均可改）
  3. 注销自动结算时，待核对/存在异议/待支付账单是否跳过站点核对、由总控直接确认？
  4. 信用额度扣至 0 后，解除「无法游戏/无法提款」的恢复条件（仅充值押金还是信用额度一并恢复）？
  5. 90 天计时的起算点与时区？
  6. 平账自动回待支付后，站点是否需要再次「核对无误」？（规则：否，直接待支付）
  7. 滞纳金「暂不收取」下线后，是否回写到实际支付总额 U？
