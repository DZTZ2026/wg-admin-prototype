1. 背景与目标

总控后台由包网服务商运营/财务使用，负责全平台站点账单的结算跟踪、异议处理与确认付款。

本期目标：

  • 实现总控「运营 → 站点账单」9 Tab 原型，与站点后台共用状态机。
  • 总控在待支付 / 已逾期 / 已坏账 / 全部账单执行「确认付款」，账单进入已支付。
  • 站点负责核对与异议；总控不代替站点点「核对无误」。
  • 沉淀可落地的开发 PRD（本页），供正式开发对照。

原型入口：/master → 运营 → 站点账单（蓝色顶栏「包网总控」）

2. 角色与边界

后台使用者数据范围账单职责
总控后台（本 PRD） 包网运营/财务 全平台 确认付款、异议账单编辑、退回待核对、全量查看
站点后台 集团/公司运营 本集团/公司 核对无误、提交异议、查看详情（详见 站点账单 PRD）

总控列表为全平台账单；站点列表仅本集团/公司。同一账单状态在两侧实时一致。

3. 账单状态机

待下发 ──(系统：自然月结束后计算产生)──→ 待核对 │ ├─ 站点：核对无误 ──────────────────────────→ 待支付 │ │ │ ├─ 总控：确认付款 ──→ 已支付 │ └─ 系统：账单月月底，透支信用额度且未平账 ──→ 已逾期 │ │ │ ┌─ 系统：已逾期超过 90 天 ──→ 已坏账 │ ├─ 总控：已逾期 Tab「已坏账」+ 备注 ──→ 已坏账 │ │ │ ├─ 平账：填补透支信用额度 ──→ 待支付 ──(总控确认付款)──→ 已支付 │ └─ 总控：确认付款（未平账时）──→ 已支付 │ └─ 站点：存在异议 ──→ 存在异议 │ ├─ 总控：安排商务对接处理 ├─ 处理完成后：总控「退回待核对」──→ 待核对 └─ 总控/站点：编辑 已坏账 ──(平账：填补透支信用额度)──→ 待支付 ──(总控确认付款)──→ 已支付

平账：站点填补透支的信用额度后触发；已逾期 / 已坏账账单自动改为待支付，再由总控「确认付款」→ 已支付。

已逾期：账单透支信用额度，且账单月月底仍未平账。

已坏账：已逾期账单超过 90 天 自动进入；或总控在「已逾期」Tab 手动点击「已坏账」并填写备注移入。

3.1 运营期费用扣款与站点限制

站点运营过程中产生的费用由系统实时扣减：押金 → 信用额度（授信额度）→ 0。信用额度扣至 0 时 C 端无法游戏、无法提款。平账指填补透支信用额度；平账后已逾期/已坏账自动回待支付，总控确认付款后变已支付。

3.2 站点注销自动结算

站点注销完成后，系统自动触发该站点站点账单最终结算，汇总未结清及在途费用（细则见 §11 待确认）。

4. 页面结构

导航：运营 → 站点账单

子 Tab（9）：待下发 · 待核对 · 待支付 · 存在异议 · 已逾期 · 已支付 · 已坏账 · 全部账单 · 账单明细

顶部按钮：查看汇率（各 Tab）；导出报表（已支付 / 全部账单 / 账单明细）

底部：待支付可批量确认付款；其余列表展示条数；金额单位说明为 U。

6. 总控侧操作与弹窗

6.1 确认付款

  • 入口：待支付、已逾期、已坏账操作列；全部账单中对应状态行；待支付底部「批量确认付款」
  • 确认文案：确认后账单状态变更为「已支付」，并进入已支付列表
  • 结果：状态 → 已支付；待支付/已逾期/已坏账列表移除；全部账单该行状态改为已支付

6.2 存在异议与商务对接

  • 站点在待核对点击「存在异议」后，账单进入存在异议 Tab，总控侧同步可见
  • 总控运营/财务收到异议账单后，安排商务对接站点线下沟通、核对争议项（可在备注/编辑中留痕）
  • 处理过程中可「编辑」调整费用明细、实际支付总额、滞纳金、推荐折扣、站长备注，状态仍为存在异议
  • 商务处理完成后，总控点击「退回待核对」，账单回到站点待核对 Tab，由站点重新核对无误或再次提出异议

6.3 已坏账（已逾期 Tab 手动移入）

  • 入口：已逾期 Tab 操作列「已坏账」；全部账单中状态为已逾期的行同样展示
  • 弹窗：二次确认 + 必填备注（写入站长备注/操作留痕）
  • 结果：账单状态 → 已坏账，移入已坏账 Tab；坏账总额 U 取实际支付总额
  • 说明：除手动移入外，已逾期超过 90 天由系统自动进入已坏账

6.4 平账与状态回退

  • 平账：站点填补透支的信用额度后，系统触发平账
  • 已逾期 / 已坏账账单平账后自动改为待支付（无需人工点核对）
  • 总控在待支付 Tab「确认付款」→ 已支付，完成款项确认

6.5 退回待核对

入口：存在异议操作列。须在商务对接处理完成后由总控操作。确认后状态 → 待核对，站点需重新核对无误或再次提出异议。

6.6 详情

与站点后台同一详情弹窗结构（见第 9 节），总控可查看全平台任意账单。

7. 关键业务规则

  1. 平账：填补透支信用额度 → 已逾期/已坏账自动改待支付 → 总控确认付款 → 已支付。
  2. 已逾期：账单透支信用额度，且账单月月底仍未平账。
  3. 已坏账：已逾期超过 90 天自动进入；或总控在已逾期 Tab 手动「已坏账」+ 备注移入。
  4. 待下发：尚未到达结算周期的账单；自然月结束后由系统计算产生，然后移入待核对。
  5. 待核对：已产生的账单，由站点操作核对无误 / 存在异议 / 详情；核对无误 → 待支付；存在异议 → 存在异议。
  6. 待支付：站点只能看详情；总控点「确认付款」→ 已支付。
  7. 存在异议：总控安排商务对接处理；处理完成后「退回待核对」，站点重新核对。
  8. 已支付：总控在待支付、已逾期、已坏账、全部账单点击确认付款后进入已支付 Tab。
  9. 核对窗口 Tooltip：待核对每月月初 6 号 00:00:00 之后可点击直接确认无误。
  10. 滞纳金：逾期每多 1 天加收账单总额 0.05%/天，上不封顶（暂不收取）。
  11. 状态变更须留痕：操作人、时间、原状态 → 新状态、备注。

8. 筛选、表格与字段

8.1 筛选

  • 账单月份；品牌字段（品牌 ID / 所属公司 / 品牌名称）；站点币种（单选）
  • 已支付 / 全部账单：账单类型（每月账单 / 一次性费用）
  • 全部账单：账单状态
  • 账单明细：月份、主站 ID、币种、游戏类型、厂商名称

8.2 列表列

品牌名称(ID)、品牌数、所属集团、所属公司、账单月份、账单类型、费用明细、实际支付总额 U、滞纳金、三方固定优惠、本月三方阶梯优惠、本月三方生效优惠、推荐折扣、账单状态、站长备注、操作时间、操作人、操作。

增列：待支付逾期倒计时；待核对/存在异议自动无误倒数；已逾期天数；已坏账「坏账总额 U」。

列不固定；斑马纹。已支付绿色；已逾期 / 已坏账 / 存在异议红色。

8.3 金额口径

  • 列表「实际支付总额 U」= 详情弹窗本账单合计，单位 U
  • 账单合计 = 游戏账单 + CDN 流量费 + 线路维护费 + 其他费用 + 费用调整
  • 实际需支付总额 U = 账单合计 + 推荐折扣
  • CDN 上限 = 当月游戏账单 × 10%，超出自动免除
  • 费用调整：财务每月 5 号前人工导入模板

9. 详情弹窗与汇率

  • 页头：所属集团、主站名称(ID)、账单月份、账单状态、站点余额（可刷新）、站长备注
  • 费用指标：游戏账单、CDN 流量费、线路维护费、其他费用、费用调整、账单合计、推荐折扣、实际需支付总额 U（带问号说明）
  • 明细表与小计；提示「*报表金额单位转换时可能存在尾数误差」
  • 查看汇率：基础币种 / 兑换币种 / 站点汇率

10. 留痕与非功能

  • 确认付款、编辑、退回待核对均写入操作人与操作时间。
  • 语言：简体中文；主题：总控蓝色顶栏（#1d39c4）。
  • 原型：本地 Mock，操作以 Message + 状态切换演示。
  • 与站点后台同域：站点 /，总控 /master。

11. 待确认项

  1. 注销自动结算的具体规则（是否强制跳过站点核对、是否自动确认付款）？
  2. 信用额度为 0 时 C 端限制的解除条件与通知方式？
  3. 确认付款是否需要谷歌验证码 / 财务二次审核？
  4. 已坏账确认付款后，坏账总额是否清零、财务报表如何回冲？
  5. 总控是否允许在待核对代站点「核对无误」？（原型：不允许）
  6. 90 天计时的起算点（进入已逾期当日还是账单月月底次日）？
  7. 平账后自动回待支付是否需要通知站点/总控？
  8. 滞纳金正式收取后，确认付款金额是否必须含滞纳金？
