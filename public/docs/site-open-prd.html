1. 背景与目标

包网 SaaS 体系中，商户/集团后台（如「伯乐 1179」）由集团或公司运营人员使用，负责发起开站、付款、查看进度，以及站点上线后的日常经营操作。

本期目标：

  • 实现开站管理模块的可交互原型，覆盖 7 个状态 Tab 及核心弹窗。
  • 明确商户后台与总控后台的职责边界，供后续双后台拆分开发。
  • 沉淀开站主链路与审核规则，作为正式开发的 PRD 基线。

不在本期：真实 API 对接、总控后台独立工程、支付扣款逻辑、谷歌验证码校验。

2. 系统边界

后台使用者与开站相关职责
商户/集团后台（本 PRD） 集团/公司运营 新增站点、查看进度、付款、上线后修改/转让/查看详情
总控后台 包网服务商运营/技术 受理申请、补充基础设施、创建中 provisioning、配置中平台费率、一审/二审审核、强制冻结
站点后台 单站运营 皮肤、语言、会员/活动等运营配置（修改弹窗提示跳转）

3. 完整开站审核流程

3.1 主链路总览

① 商户：新增站点（提交业务信息） ↓ ② 总控：受理 & 补充信息（站点 ID、OSS、备域名、商务、费率确认） ↓ ③ 创建中（总控：基础设施 provisioning） ↓ ④ 配置中（总控平台配置 + 商户可选进站点后台做运营配置） ↓ ⑤ 待审核 ├─ 一审：开站待技术审（system 系统自动） └─ 二审：人工审核（总控运营/商务，如 tempo） ↓ ⑥ 待付款（商户从集团余额/授信扣款） ↓ ⑦ 已上线（商户：修改 / 转让 / 记录 / 详情）

3.2 分阶段说明

阶段状态商户后台总控后台
0. 开站前 — 确认额度；填写新增站点表单并提交 —
1. 受理 → 创建中 查看进度 分配站点 ID、OSS、备域名、对接商务、确认费率额度
2. 创建中 创建中 仅查看（记录/详情） 创建实例、主备域名、OSS、账户初始化
3. 配置中 配置中 查看；可进站点后台配置运营项 游戏平台、默认费率；复制站点配置落地
4. 待审核 开站待技术审 仅查看（记录/详情），不可审核 一审（system）+ 二审（人工）
5. 待付款 待付款 付款操作 查看、催办
6. 已上线 已上线 修改、转让、记录、详情 全量管理、强制冻结

3.3 审批留痕（记录弹窗）

站点上线后，「记录」弹窗展示完整审批链：

  • 一审备注：审核通过 · 审批人 system · 审批时间（系统自动技术审）
  • 二审备注：审核通过 · 审批人 tempo · 审批时间（总控人工审）

3.4 关键结论

  • 商户在待审核阶段只读，审核按钮应仅在总控后台出现。
  • 商户在待付款阶段必须能付款，不能全程只读。
  • 皮肤/语言修改需跳转站点后台，不在集团后台修改弹窗内完成。
  • 转让/注销另有独立审核链：技术审（总控）+ 集团审（商户集团负责人）。

6.2 全部站点操作弹窗

修改

  • 只读：所属集团、所属公司、站点类型、客户端皮肤、语言匹配模式、语言、时区、开站费/押金/线路维护费

强制冻结

  • 绿色确认文案：站点名称 + 站点 ID + 是否冻结

  • 只读：所属集团、所属公司、站点名称
  • 转让类型：内部转让 / 外部转让
  • 内部：转让公司下拉（必填）
  • 外部：绿色提示「需审核，请联系商务」
  • 备注、谷歌验证码（必填）

记录

  • 站点档案 + 审批信息（一审/二审备注、审批人、时间）
  • 底部仅「关闭」

详情

  • 三栏摘要：站点配置、财务额度、运营网络信息
  • 游戏平台筛选表：游戏类型、平台名称、币种、默认费率、调整后价格

10. 异常与分支流程

10.1 审核拒绝

待审核 → 一审/二审拒绝 → 已拒绝 → 商户查看原因 → 可修改后重新提交。

10.2 付款超时

待付款长期未付 → 待关闭 → 可能进入已注销流程。

10.3 转让（上线后）

  • 内部转让：转让待技术审 → 转让待集团审 → 完成
  • 外部转让：联系商务 → 转让待技术审 → 待外部接收 → 完成

10.4 注销（上线后）

注销待技术审 → 注销待集团审 → 已注销

10.5 强制冻结

需谷歌验证码 + 备注；状态变为强制冻结；已注销行仅保留记录/详情操作。

11. 非功能需求

  • 语言：简体中文
  • 主题：商户后台红色顶栏（#d72c2c），表格与 Ant Design 5 组件规范
  • 原型阶段：本地 Mock 数据，操作成功以 Message 提示
  • 响应式：筛选区在宽屏不换行；小屏可横向滚动

12. 待确认项

  1. 强制冻结在商户后台是否开放，或仅总控可操作？
  2. 配置中阶段商户是否必须在站点后台完成配置才能进入待审核？
  3. 待付款超时规则与自动关闭天数？
  4. 二审审批人角色定义（商务 vs 运营 vs 风控）？
  5. 已注销站点是否允许重新开站（同域名/同名称）？

13. 总控后台 · 开站管理

包网服务商运营/技术人员使用的总控后台同样具备「开站管理」模块，Tab 结构与商户后台一致（7 个 Tab），但列表范围、数据来源、操作列能力不同。

13.1 列表范围与数据来源

来源触发方式初始状态
商户申请商户后台「新增站点」提交进入总控受理 → 创建中
总控创建总控后台「新增开站」直接新建创建中（可预填 OSS、备域名、商务等）

总控列表为全平台站点；商户列表仅为本集团/公司相关站点。总控表格增加「来源」列及筛选项。

13.2 总控顶部操作

  • 新增开站（P0）：总控直接创建，表单在商户字段基础上增加 OSS 厂商、备域名、对接商务等
  • 导出报表、批量操作（P2）

13.3 总控各 Tab 操作列（状态推进）

总控通过操作列直接改变站点状态，每次变更需留痕（操作人、时间、原状态→新状态、备注）。

14. 双后台对比与状态推进

14.1 能力对比

能力商户后台总控后台
列表范围本集团/公司全平台
新增新增站点新增开站 + 接收商户申请
创建中~待审核仅查看推进/回退状态
待审核不可审核审核通过/拒绝
待付款付款确认到账 / 催办 / 关闭

14.2 统一状态机（谁触发跳转）

商户新增 ──┐ 总控新增 ──┼──→ 创建中 ──(总控：进入配置中)──→ 配置中 ──(总控：提交审核)──→ 待审核 │ ↑ │ 总控：审核通过 / 拒绝 │ ↓ └────────────────────────────────── 待付款 ──(商户付款 或 总控确认到账)──→ 已上线

14.3 状态变更留痕

总控每次状态推进写入「记录」：操作人、操作时间、原状态 → 新状态、备注。与上线后「记录」弹窗中的审批信息结构一致，便于审计。
